## 1. 实施结论

本次适配已经把数据组成、训练采样和测评协议从模型方法变量中分离出来：

- B0 与 H1 使用相同 WHU-MARS-1000 split、相同 RGB/IR/Thermal 元数据、相同 Ground/Aerial 标签、相同 sampler、seed、batch、增强、optimizer、LR、scheduler 和 60-epoch 预算。
- 两份配置只允许在 `HIHR_MODE`、`WITH_FUSION`、`WITH_HIERARCHY` 和 `OUTPUT_DIR` 上不同。
- B0 只训练和拼接 CLIP final class token `x` 与 projection `xproj`；不构建或执行 prompt、TMF、HHL 和 tree heads。
- H1 保留当前官方代码定义的 `x + xproj + parent + child` 推理特征和全部 HiHR loss。
- 两者均绕过 HiHR 原 Market-style rank 路径，进入独立 `WHU_AS_REID` evaluator；不会执行原代码中的 Cython rank 编译和 same-PID-and-camera 过滤。

因此，B0 与 H1 之间是可解释的 matched control。它们与 UAD/UAD baseline 之间属于**相同 AS-ReID 测评协议下的结果比较**，不是相同训练 recipe 的消融比较。

## 2. 代码改动

### 2.1 数据与元数据

- 新增 `fastreid/data/datasets/whu_mars.py`。
- 数据 tuple 为 `(img_path, pid, camid, view, modality)`。
- 官方目录名 `RGB/IR/Thermal` 原样保存；进入 batch 后映射为 `modalityids=0/1/2`，报告时对应 `RGB/NIR/TIR`。
- camera 映射固定为 `c1-c5 -> Ground`、`c6-c7 -> Aerial`。
- `DATASETS.ROOT` 取代原来硬编码的 `/yqw/DATA/`。
- 对其他 HiHR 数据集，tuple 第 5 项若不是合法 modality 字符串，则 `modalityids=-1`，不会把原 attribute tensor 错当 modality。

### 2.2 Stratified PKM-View sampler

正式 batch contract：

```text
P_AG=5, P_G=5, M=3, K=2
batch = (5 + 5) × 3 × 2 = 60 images
```

- 5 个 cross-view PID：每个 modality 抽 `1 Ground + 1 Aerial`。
- 5 个 Ground-only PID：每个 modality 抽 `2 Ground`。
- 每批三模态各 20 张、Ground 45 张、Aerial 15 张。
- sampler 使用独立 `RandomState(SEED)`；DataLoader 也使用由 `SEED` 初始化的独立 generator，避免 B0/H1 模型初始化路径影响样本顺序和增强 worker seed。
- sampler 明确限制 `WORLD_SIZE=1`，与本项目的单卡实验约束一致。

### 2.3 B0/H1 模型分支

| 项目 | B0 | H1 |
|---|---|---|
| `x` CE + triplet | 开 | 开 |
| `xproj` CE + triplet | 开 | 开 |
| prompt/TMF | 关 | 开 |
| parent/child heads | 关 | 开 |
| HHL/entailment | 关 | 开 |
| child intra-view triplet | 关 | 开 |
| 推理维度 | 1280 | 2304 |

共享的 global heads 使用固定、隔离的初始化 seed，因此不会因 H1 多构建专属模块而改变 B0/H1 共用 head 的初始随机流。

### 2.4 UAD 同构测评器

overall 主协议严格执行：

1. 合并三模态 query，共 6,405 张；合并三模态 gallery，共 93,609 张。
2. 对 query/gallery 特征做 L2 normalization。
3. 计算 squared Euclidean distance，并对完整 gallery 排序；`TOP_K_EVAL=0`，不截断。
4. 对每个 query 删除所有 `gallery_camid == query_camid` 项，不附加 PID 条件。
5. 报告 mAP、Rank-1、Rank-5、Rank-10；关闭 AQE、test flip 和 re-ranking。
6. 训练期只做 overall；最终独立复评才开启 3×3 modality 与 2×2 view 诊断，避免每次训练评估重复执行 13 次完整排序。

`metric=(mAP+Rank-1)/2` 只用于兼容 HiHR 的 checkpoint hook；正式结果固定读取 `model_final.pth`，不使用 `model_best.pth` 做结论。

## 3. 与 UAD/UAD baseline 的可比性

### 3.1 可以比较的结论

允许表述：

> 在相同 WHU-MARS-1000 AS-ReID overall 测评协议下，HiHR baseline/完整 HiHR 的 mAP 或 Rank-k 高于（或低于）UAD baseline/完整 UAD。

原因是 HiHR 新 evaluator 与 UAD 当前 evaluator在以下关键点一致：相同 query/gallery 聚合、L2 normalization、full ranking、全同相机 gallery 排除、mAP/CMC 计算、无 reranking。

### 3.2 不能从该表推出的结论

- 不能将跨仓库差值因果归因成 TMF/HHL 本身优于或弱于 ProCA/GPD。
- 不能把不同 backbone 初始化、训练轮数、sampler、batch 和 optimizer recipe 当成已匹配变量。
- 单 seed 结果不能表述为统计显著。

### 3.3 当前 UAD 参考阈值

当前本地 UAD 归档文档 `E:\CVPR2027\CVPR26_UAD\doc\7.统一公平基线初步实验结果与UAD复现分析_0921.md` 记录的固定 epoch-120 独立复评为：

| 参考方法 | mAP | Rank-1 | Rank-5 | Rank-10 |
|---|---:|---:|---:|---:|
| UAD baseline（V1） | 8.46 | 22.01 | 39.08 | 48.12 |
| 完整 UAD（V4） | 10.16 | 27.34 | 44.14 | 52.37 |

正式 HiHR 结果表应逐指标比较，不预先把“超过”压缩成单个 composite 判据。模态对诊断使用单模态 gallery，不能与 overall 三模态异构 gallery 指标混为一谈。

```bash

```

预检必须依次出现：

```text

WHUMARS_MODEL_SMOKE_OK
mode baseline
feature_shape (2, 1280)
WHUMARS_MODEL_SMOKE_OK

feature_shape (2, 2304)
```

任一步报错均停止，不自动重试、不进入正式训练。预检会执行 B0/H1 各一个 batch 的 AMP forward/backward，但不会 optimizer step，也不会产生正式 checkpoint。
