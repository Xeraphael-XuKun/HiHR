## 1. 结论先行

你的核心判断是合理的：

1. **Ground/Aerial 必须继续作为 HiHR 的层级条件。** HiHR 的 view-aware prompt、child feature 选择和 child-level intra-view triplet 都直接依赖 Ground/Aerial 标签，不能把六种 `(modality, viewpoint)` 场景简单压成一个标签，更不能只保留 modality。
2. **RGB/NIR/TIR 必须作为独立 metadata 保存。** modality 不应替代 HiHR 的两视角层级，但必须进入 dataset item、sampler 和 evaluator，用于构造跨模态 batch、AS-ReID 聚合评测及 3×3 模态诊断。
3. **不能继续使用原始 `NaiveIdentitySampler`。** 它只保证每个身份有 `K` 张图，不保证三模态覆盖，也不保证 Ground/Aerial 覆盖，无法稳定支持 HiHR 的 child-level intra-view supervision。
4. **也不能原样复制 WHU-MARS 的 `PKMSampler`。** 原 sampler 只平衡 identity × modality，不识别 viewpoint；其 tuple-index batch 和 tri-modal collate 也与 HiHR 的单图 FastReID 数据流不兼容。
5. **需要把“PKM + 视角均衡”精确定义成条件式均衡。** 当前 WHU-MARS-1000 训练集 500 个身份中，仅 216 个身份同时含 Ground/Aerial，另 284 个身份只有 Ground。若强制所有身份都按 Ground/Aerial 1:1 采样，将直接丢弃 284 个训练身份，方案不可接受。

因此推荐的第一版为：

> **分层 PKM-View sampler：`P=10, M=3, K=2`，每批固定抽取 5 个跨视角身份和 5 个 Ground-only 身份。跨视角身份在每个 modality 内抽 1 Ground + 1 Aerial；Ground-only 身份在每个 modality 内抽 2 Ground。每批共 60 张图。**

这不是全局 1:1 view balance，而是：

- 对具备双视角数据的身份，在每个 modality 内严格 1:1；
- 对缺失 Aerial 的身份不伪造样本、不丢弃身份；
- 每批稳定包含 Aerial 样本和跨视角正样本；
- 整批 Ground:Aerial 为 `45:15 = 3:1`，与本地训练集自然比例 `68,190:23,943 ≈ 2.85:1` 接近。

## 2. 论文事实

### 2.1 HiHR

HiHR 的方法链为 MFE → TMF → HHL：

- MFE 从 CLIP ViT 的多层 token 提取多粒度视觉特征，并使用 view-agnostic 与 view-aware prompts（HiHR 论文第 4–5 页）。
- TMF 用文本特征查询多层 class/patch tokens，输出 view-agnostic parent feature 与 view-aware child feature（第 5 页）。
- HHL 将 parent/child 映射到 Lorentz hyperbolic space，通过尺度分离和 entailment cone 建立 coarse-to-fine 层级（第 6–8 页）。
- parent 使用跨视角混合 supervision；child 的 triplet positives/negatives限制在同一视角内（第 8 页）。
- 推理时，论文描述为将 parent/child 映回欧氏空间后拼接（第 8 页）。
- 论文训练设置为 CLIP ViT-B/16、`256×128`、batch size 64、每身份 4 张、Adam、60 epochs；预训练模块 LR `5e-6`、新模块 LR `3.5e-4`（第 9 页）。
- 论文中的 baseline 是 CLIP ViT-B/16 + cross-entropy + triplet；TMF 和 HHL 依次作为增量模块（第 10–11 页，Table 4）。

### 2.2 WHU-MARS

- WHU-MARS 将 scenario 定义为 `modality × viewpoint`，其中 modality 为 RGB/NIR/TIR，viewpoint 为 Ground/Aerial（WHU-MARS 论文第 5 页，Eq. 1）。
- AS-ReID 使用一个共享模型，从任意 query 场景检索异构 gallery（第 1–2、5 页）。
- 官方 baseline 使用 `P×M×K` sampler：每批 `P` 个身份、每身份每 modality 采 `K` 张图（第 5–6 页）。
- WHU-MARS-1000 支持三模态配对，但 AS-ReID 本身不要求图像级同步配对（第 4–5 页）。
- AS-ReID 评测要求排除与 query 相同 camera 的全部 gallery 图像，而不是只排除“同 PID 且同 camera”的图像（第 5 页，Eq. 2）。

## 3. 当前代码事实与需要正视的差异

### 3.1 HiHR 官方仓库

1. `fastreid/data/datasets/*` 产出 `(img_path, pid, camid, viewid)`；`CommDataset` 将 `viewid` 传入 batch。
2. `NaiveIdentitySampler` 仅按 PID 建索引，不读取 camera、view 或 modality。
3. `baseline_vit_hihr.py` 将字符串标签映射为 `Ground=0, Aerial=1`。
4. `vit_hihr.py` 使用 `viewids + 1` 从两个 view-private prompt 中选择当前样本的 child prompt。
5. child triplet 在 `baseline_vit_hihr.py::view_unique_triplet_loss` 中被拆成 Aerial 子集和 Ground 子集分别计算。
6. 当前 `WITH_FUSION`/`WITH_HIERARCHY` 不是完整的结构开关：`vit_hihr.py` 无论开关值如何都会执行 prompt、TMF 和 hyperbolic path；只把配置改成 `False` 不能得到真实 baseline。
7. 当前 full 模型训练时还对 CLIP final feature `x` 和 projected feature `xproj` 施加 CE/triplet；推理时拼接 `x + xproj + parent + child`。这比论文第 8 页只描述 parent+child 拼接更宽。
8. 当前 HiHR YAML 使用 `MultiStepLR`、steps `[20, 30]`，而论文第 9 页写 cosine schedule。
9. optimizer 代码将 `backbone.pretrained_*` 的 LR 固定为 `5e-6`，与论文一致；其他模块使用 `BASE_LR=3.5e-4`。
10. 数据根目录目前硬编码为 `/yqw/DATA/`，需要改成配置项，不能直接用于本地或 sensecore 路径。

### 3.2 WHU-MARS 官方实现

1. `datasets/whu_mars.py` 按 RGB/IR/Thermal 文件夹分别保存样本，tuple 第 4 项是 modality id；没有显式 viewpoint 字段。
2. `PKMSampler` 为每个 PID、每个 modality 建索引，但不区分 Ground/Aerial。
3. 它的 `batch_size=64` 是逻辑 `P×K` 数；每个逻辑 index 实际返回三个 modality index，模型前向图像数是 `64×3=192`。
4. 这种 tuple-index + tri-modal collate 是 UAD 数据流的一部分，不能直接塞入 HiHR 的单图 `CommDataset`。
5. WHU evaluator 使用 `remove = (g_camids == q_camid)`，符合 AS-ReID 的全同相机排除；HiHR 的 FastReID evaluator 当前只移除 `(same PID) AND (same camera)`，不能直接复用。

## 5. 推荐 sampler：Stratified PKM-View

### 5.1 定义

记：

- `M = {RGB, NIR, TIR}`；
- `I_AG` 为同时含 Ground/Aerial 的身份集合，`|I_AG|=216`；
- `I_G` 为只有 Ground 的身份集合，`|I_G|=284`；
- `P_AG=5, P_G=5, P=P_AG+P_G=10`；
- 每身份每 modality 采 `K=2`。

每个 batch：

1. 从 `I_AG` 抽取 5 个身份，从 `I_G` 抽取 5 个身份；
2. 对 `y ∈ I_AG` 和每个 `m ∈ M`：抽取 `1 Ground + 1 Aerial`；
3. 对 `y ∈ I_G` 和每个 `m ∈ M`：抽取 `2 Ground`；
4. 将样本作为普通单图 index 展平交给 HiHR `CommDataset`，不使用 UAD 的 tuple-index collate。

因此：

```text
batch images = P × M × K = 10 × 3 × 2 = 60
Aerial images = 5 × 3 × 1 = 15
Ground images = 5 × 3 × 1 + 5 × 3 × 2 = 45
```

### 5.2 为什么选择 `P=10, K=2`

- 总 batch 60 接近 HiHR 官方 batch 64，避免直接复制 WHU `P=16, K=4` 后得到 192 张图，显著改变显存、优化噪声和 batch-hard negative 数量。
- 每个跨视角身份拥有 3 个 Aerial 和 3 个 Ground 样本，可为 child intra-view triplet 提供真实同身份正样本；`K=1` 做不到这一点。
- 每批 Ground:Aerial 为 3:1，接近训练集自然比例，同时保证每批一定含 Aerial。
- `P_AG:P_G=5:5` 会让跨视角身份相对 Ground-only 身份约多 `284/216≈1.31×` 的期望曝光；这是明确、可记录的 view-support 重加权，而不是隐藏的数据丢弃。

### 5.3 sampler 行为约束

- baseline 与 full **必须使用完全相同的 sampler、seed、batch 组成规则和 epoch iteration 数**。
- 身份池和样本池使用独立、可复现的 RNG；单卡实验固定 `WORLD_SIZE=1`。
- 各 group 优先循环无放回取样；只有 group 数量不足本批需求时才允许有放回。当前 WHU-MARS-1000 不会触发该 fallback。
- 不按 frame index 绑定三模态；sampler 只保证 identity × modality × viewpoint 组成，不引入 synchronized-triplet 模型假设。
- 每个 batch 记录一次紧凑统计：unique PID、modality counts、view counts、跨视角身份数；不要增加复杂 hash 或 CI。

### 5.4 不采用的方案

| 方案 | 不采用原因 |
|---|---|
| 原始 HiHR `NaiveIdentitySampler` | 无 modality/view 保证，child intra-view triplet 可能只有 self-positive |
| 原样 WHU `PKMSampler` | 不区分 view；tuple-index/collate 与 HiHR 不兼容；实际 192 图 batch 改变训练口径 |
| 所有身份严格 Ground:Aerial=1:1 | 会排除 284 个 Ground-only 身份，造成严重选择偏差 |
| 把 6 个 scenario 当成 6 个 HiHR view | 破坏 HiHR coarse Ground/Aerial 与 fine view-specific 的原始语义，并把 modality shift 错当 viewpoint |
| 为缺失 Aerial 的身份复制 Ground 并标成 Aerial | 标签造假，会污染 view-aware prompt 和 intra-view loss |


## 7. 两组实验的严格定义

### 7.1 B0：HiHR baseline

使用 CLIP ViT-B/16 的 final class token 与 projected class token：

```text
f_global = x
f_proj   = xproj
```

训练损失：

\[
\mathcal L_{B0}=
\mathcal L_{CE}(x)+\mathcal L_{Tri}(x)+
\mathcal L_{CE}(x_{proj})+\mathcal L_{Tri}(x_{proj}).
\]

推理特征：

```text
concat(x, xproj)
```

B0 不构建或不执行：

- dual-level prompts；
- multi-layer token fusion / TMF；
- parent/child tree heads；
- hyperbolic exp/log map；
- entailment losses；
- child intra-view triplet。

这一定义沿用 full 代码已有的两个 global branches，是对当前官方实现最直接的结构消融；不能仅将 `WITH_FUSION=False`、`WITH_HIERARCHY=False` 后继续跑完整 forward。

### 7.2 H1：完整 HiHR

保留当前官方代码的四路输出：

```text
x + xproj + parent(view-agnostic) + child(view-aware)
```

在 B0 损失上增加：

\[
\mathcal L_{H1}=\mathcal L_{B0}
+\mathcal L_{CE}(g^p)+\mathcal L_{Tri}(g^p)
+0.25\mathcal L_{CE}(g^c)+\mathcal L_{Tri,intra}(g^c)
+5\mathcal L_{entail}.
\]

其中 `L_entail` 按当前代码由以下三项 scalar 组成：

- identity parent prototype → child image；
- parent prompt → child prompt；
- same-level prompt → image（内部覆盖 parent 与 child）。

推理特征按当前官方代码使用：

```text
concat(x, xproj, parent, child)
```

### 7.3 唯一方法变量

| 项目 | B0 baseline | H1 full HiHR |
|---|---|---|
| 数据 split | 相同 | 相同 |
| sampler | 相同 Stratified PKM-View | 相同 Stratified PKM-View |
| batch | 60 | 60 |
| backbone / 初始化 | 相同 CLIP ViT-B/16 | 相同 CLIP ViT-B/16 |
| augmentation | 相同 | 相同 |
| optimizer / LR / scheduler / epochs | 相同 | 相同 |
| global CE + triplet | 开 | 开 |
| TMF | 关 | 开 |
| HHL / entailment | 关 | 开 |
| child intra-view supervision | 关 | 开 |

因此 `H1 - B0` 只解释为“在同一 WHU-MARS 适配和采样协议下加入 HiHR 专属 TMF/HHL 路径后的整体增量”，不能进一步拆分 TMF 与 HHL 的独立贡献。

## 9. 评测协议适配

### 9.1 主指标

使用 WHU-MARS-1000 AS-ReID：

- query：RGB/NIR/TIR 三个 query 子集全部合并，共 6,405；
- gallery：RGB/NIR/TIR 三个 gallery 子集全部合并，共 93,609；
- 特征 L2 normalize 后使用 squared Euclidean distance（排序与 normalized cosine 等价，代码路径与 UAD 一致）；
- 对每个 query 删除 `gallery_camid == query_camid` 的全部 gallery 项；
- 报告 mAP、Rank-1、Rank-5、Rank-10；
- 不使用 re-ranking。

### 9.2 诊断指标

从同一 epoch-60 checkpoint 和同一次特征导出中额外报告：

- 3×3 modality pair：RGB/NIR/TIR query → RGB/NIR/TIR gallery；
- view pair：A→G、G→A、G→G；A→A 在全同相机过滤后没有有效 query，报告 `NaN` 与 `valid_queries=0`；
- B0 与 H1 的每项绝对差值。

这些诊断不参与 checkpoint 选择。补充复评 `model_best.pth` 时，B0/H1 必须成对执行相同协议，并标记为 `test-selected exploratory screening`；正式结论仍使用预先固定的 epoch-60 `model_final.pth`。

### 9.3 evaluator 必修项

HiHR 原 `evaluate_rank` 的 same-PID-and-camera 过滤不符合 WHU AS-ReID。适配实现采用独立协议开关：

```text
TEST.PROTOCOL = "WHU_AS_REID"
```

只在 WHU-MARS 配置中启用；其他 HiHR 数据集继续保持原 Market1501-style 逻辑。

10. 一个轻量 smoke 脚本：只验证 dataset、sampler、loss keys、forward/backward 和 evaluator 过滤，不建设大规模单元测试体系。

不建议：

- 将 `CVPR26_UAD` 的 dataloader/model 整体复制进 HiHR；
- 重写 FastReID 训练框架；
- 在第一轮同时加入 modality-specific branch、modality prompt、UAD loss 或六场景层级；
- 为了“防御性”覆盖异常数据而增加复杂 fallback、hash 或 CI。

## 11. 实施前验收门槛

### Gate A：dataset

- train/query/gallery 必须打印为 `92,133 / 6,405 / 93,609`；
- 每个 split 三模态数量必须相等；
- camera 必须是 7 个；
- train 必须识别 `216` 个跨视角身份、`284` 个 Ground-only 身份；
- `c1-c5=Ground, c6-c7=Aerial` 的 train/gallery 平台总量必须与官方统计一致。

### Gate B：sampler

连续抽查不少于 20 个 batch，每批必须满足：

```text
10 unique PIDs
RGB/NIR/TIR each 20 images
15 Aerial + 45 Ground
5 cross-view PIDs + 5 Ground-only PIDs
cross-view PID: each modality exactly 1 Ground + 1 Aerial
Ground-only PID: each modality exactly 2 Ground
```

### Gate C：模型与梯度

- B0 loss keys 只能包含两路 global CE/triplet；
- B0 的 prompt/TMF/HHL 参数不得产生梯度，最好不进入 forward；
- H1 必须包含 global、parent、child、entailment losses；
- H1 Aerial/Ground child 子集均非空，每个跨视角身份在两子集中均有真实正样本；
- 一次 AMP forward/backward 后所有总损失、梯度和 hyperbolic 参数有限。

### Gate D：评测

- 使用同一组固定特征，适配后的 HiHR evaluator 与 `CVPR26_UAD/utils/metrics.py` 在 overall mAP/CMC 上数值一致；
- 显式构造 same-camera distractor，确认其被全部过滤；
- query/gallery 数量及 3×3 modality pair 数量正确。

### Gate E：实验启动

- 本地 dataset/sampler smoke 已通过，UAD evaluator 数值对齐已通过；
- B0/H1 最小 forward/backward 由指定 `llmpar` 解释器在 A800 预检中完成；
- 当前授权覆盖代码实施，不等同于已授权或已启动正式训练；
- sensecore 正式训练每组单卡、独立前台命令，`CUDA_VISIBLE_DEVICES=0`、`WORLD_SIZE=1`，不以预检通过替代训练已启动。

## 12. 结果解释边界

两组实验可以回答：

> 在相同 WHU-MARS-1000 数据、相同 Stratified PKM-View sampler、相同 CLIP backbone 与训练预算下，加入当前官方代码定义的 TMF + HHL 是否改善 AS-ReID。

不能直接回答：

- TMF 与 HHL 各自贡献多少；
- 新 sampler 相比 NaiveIdentitySampler 或原 WHU PKM 的独立收益；
- TMF/HHL 本身是否优于 ProCA/GPD；两者训练 recipe、backbone、loss 和 batch 均不同，不能做模块级因果归因；
- 结果是否严格复现 HiHR 论文，因为 scheduler 与推理特征采用 code-faithful 而非 paper-strict 口径；
- WHU-MARS-2337 上是否同样成立；首轮只覆盖 WHU-MARS-1000。

建议的成功判据不是预设必须提升多少，而是：

1. H1 相比 B0 的 overall mAP 和 Rank-1 方向一致；
2. A→G/G→A 不出现明显系统性退化；
3. 增益不是仅由某一个 RGB/NIR/TIR pair 驱动；
4. 训练稳定，child intra-view loss 具有真实正样本支持；
5. 结论只基于固定 epoch-60 checkpoint，不混用各指标的 test-set 峰值。

在用户确认的论文表述边界内，可以将 B0/H1 的固定 epoch-60 指标与 UAD baseline/UAD 的固定 checkpoint 指标放在同一张表中，并表述为“在相同 WHU-MARS-1000 AS-ReID 测评协议下，某方法取得更高的 mAP/Rank-k”。该比较是**同协议结果比较**，不是训练 recipe matched control，也不能进一步写成 TMF/HHL 对 ProCA/GPD 的模块级优越性结论。
